1. Purpose and CBSE Weightage of the Practical File

In CBSE Class 10 Information Technology (Subject Code 402), 50 marks are allotted to Theory Examination and 50 marks are awarded through Practical Evaluation. The practical marks are broken down as follows:

Practical Assessment ComponentMarks Allotted
Practical Hands-on Examination (Lab Test): Writer/Calc/Base execution20 Marks
Practical File / Student Digital Portfolio: Minimum 15-20 documented lab exercises10 Marks
Viva Voce: Oral questioning by the external and internal examiners10 Marks
Project Work / Field Visit Report: Integrated real-world case project10 Marks
Total Practical Marks:50 Marks

2. Standard Practical File Structure & Layout

To secure maximum marks from the external examiner, your practical file must adhere to this professional order:

  1. Front Cover Page: School Name, School Logo, "CBSE Class 10 IT (402) Practical File", Academic Session (2025-2026), Student Name, Roll Number, and Class/Section.
  2. Certificate of Authenticity: Formal certificate signed by the IT Teacher, Principal, and External Examiner.
  3. Acknowledgment: A polite note acknowledging the school principal, computer teacher, and parents.
  4. Index Page: S.No., Date, Practical Title / Aim, Page Range, Teacher's Signature.
  5. Practical Exercises: Minimum 15 detailed exercises with Aim, Requirements, Step-by-Step Procedure, Output Screen, and Teacher Remarks.
  6. Viva Voce Study Notes: Key definitions and command cheat sheet for rapid oral review.

3. Unit 1: Digital Documentation (Advanced) Practical Exercises

  • Practical 1 (Custom Styles): Create a document with custom paragraph styles (Title, Subheading, Content) using the Styles panel and apply them across multiple headings.
  • Practical 2 (Images and Text Wrapping): Insert an image, crop unwanted sections, apply corner resizing maintaining aspect ratio, and demonstrate different text wrapping modes (Optimal, Wrap Through, Parallel).
  • Practical 3 (Drawing Objects & Grouping): Create a flowchart using basic shapes, arrows, and callouts; group them into a single object and demonstrate moving/rotating.
  • Practical 4 (Custom Templates): Design a professional school newsletter or project cover page, save it as a reusable template (.ott), and generate a new document from it.
  • Practical 5 (Table of Contents): Structure a 5-page report with Heading 1, 2, 3 levels; generate an automatic Table of Contents, modify document headings, and demonstrate updating the TOC.
  • Practical 6 (Mail Merge Letters): Design a formal parent-teacher invitation letter; connect an external data source with student details; insert merge fields (<Student_Name>, <Class>, <Attendance>) and print/save merged copies.

4. Unit 2: Electronic Spreadsheets (Advanced) Practical Exercises

  • Practical 7 (Data Consolidation): Consolidate monthly sales figures from three sheets (Jan, Feb, Mar) into a Q1 Summary sheet using the SUM function and row/column headers.
  • Practical 8 (Subtotals): Sort an employee payroll dataset by Department; apply the Subtotals tool to calculate total and average salaries per department and grand totals.
  • Practical 9 (What-If Scenarios): Set up an annual school picnic budget; create three Scenarios (Budget Trip, Standard Trip, Luxury Trip) and compare expenditure totals.
  • Practical 10 (Goal Seek): In an academic report card, calculate the minimum marks required in the final subject to achieve an overall 85% aggregate using Goal Seek.
  • Practical 11 (Linking Multiple Sheets): Create formulas linking cells across multiple sheets (e.g., ='Term1'.B4 + 'Term2'.B4) and create an external hyperlink jumping to a separate workbook.
  • Practical 12 (Recording Changes & Macros): Enable change tracking (Track Changes > Record), make edits, and use the Accept/Reject dialog. Then record a Macro to format table headers with a light blue background and bold text.

5. Unit 3: Database Management System (Base & SQL) Practical Exercises

  • Practical 13 (Table Creation in Design View): Create a table Students with columns RollNo (Integer, Primary Key), Name (Varchar), DOB (Date), and Fees (Decimal).
  • Practical 14 (Table Relationships & Referential Integrity): Create a child table IssuedBooks with BookID (PK) and RollNo (FK); open the Relationships window and establish a One-to-Many link with Referential Integrity enabled.
  • Practical 15 (SQL Queries): Write and execute SQL queries:
    • SELECT * FROM Students WHERE Fees > 25000 ORDER BY Name ASC;
    • UPDATE Students SET Fees = Fees + 2000 WHERE RollNo = 101;
    • DELETE FROM Students WHERE RollNo = 115;
  • Practical 16 (Forms & Reports): Create a user-friendly Form using the Form Wizard with formatted buttons; design a printable Report grouped by Class using the Report Wizard.

6. Unit 4: Web Applications & Security Practical Exercises

  • Practical 17 (Accessibility Configuration): Configure Windows Accessibility settings: activate StickyKeys, FilterKeys, and ToggleKeys, and document the behavior of SoundSentry and High Contrast with screenshots.
  • Practical 18 (Offline Blogging): Install an offline blog editor (or simulate using Qumana/Word); draft an informative post on Cyber Hygiene and demonstrate drafting and previewing.
  • Practical 19 (Online Transaction Simulation): Document step-by-step safety measures for booking a train ticket on IRCTC or buying a book on an e-commerce platform (identifying HTTPS, padlock, OTP).
  • Practical 20 (Workplace Ergonomics Audit): Perform an ergonomic assessment of your school computer laboratory; identify 5 potential hazards (loose wires, monitor glare, chair height) and suggest corrective solutions.

7. Best Practices for Taking Clear Screenshots & Documentation

  • Capture Relevant Area: Use Snipping Tool (Win + Shift + S) to capture the specific active dialog or calculation table instead of full clutter screens.
  • Annotation: Draw clean red arrows or boxes highlighting key buttons (e.g., pointing to the Goal Seek target cell or Primary Key icon).
  • High Resolution: Do not stretch or distort captured screenshots. Maintain standard 100% DPI resolution.
  • Include Captions: Every screenshot in the file must have a figure caption (e.g., Fig 2.1: Consolidate Dialog Box Settings).

8. Writing Learning Reflections & Problem Solving Logs

A high-scoring portfolio includes a brief 3-4 sentence Learning Reflection after each practical:

  • What was the core learning objective? (e.g., "I learned how absolute references prevent calculation errors when copying formulas.")
  • What error or obstacle occurred during the lab? (e.g., "Initially, Subtotals showed multiple duplicate group rows because I forgot to sort the table by Department first.")
  • How was the problem resolved? (e.g., "I selected the table and sorted the Department column from A to Z, which produced clean, grouped subtotal rows.")

10. High-Yield Practical Viva Voce Questions and Answers

1. Why do we need a primary key in a database table?
A primary key uniquely identifies each record and prevents duplicate or NULL rows, ensuring data integrity.

2. What is the difference between Goal Seek and standard formulas in Calc?
Standard formulas calculate an output from known inputs (forward calculation). Goal Seek calculates the required input value when the final desired output is already known (reverse calculation).

3. Why must data be sorted before applying Subtotals?
If data is not sorted, records of the same category are scattered, leading to fragmented subtotal rows instead of unified category summaries.

4. What is the difference between DDL and DML in SQL?
DDL (Data Definition Language) commands like CREATE and ALTER define table structures. DML (Data Manipulation Language) commands like SELECT, INSERT, and UPDATE manage actual table records.

5. Which feature helps users with hand tremors avoid accidental double key-presses?
FilterKeys.

6. What does the PASS rule represent during a fire emergency?
P - Pull the pin, A - Aim at base of fire, S - Squeeze the handle, S - Sweep side to side.
